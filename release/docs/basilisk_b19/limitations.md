# BASILISK-B1.9 局限与诚实声明

本文件记录 B1.9 的已知局限。**最重要的一条在 §1** —— 它削弱了本阶段
Gate 10 的证明力，必须先读。

---

## 1. `HI_D_obs` 是 recomputation，不是 estimation

`HI_D_obs` 与 B1.8 内部累积损伤的一致性达到机器精度：

| 量 | 值 |
|---|---|
| correlation 最小值 | 1.00000000 |
| RMSE 最大值 | 2.737e-09 |
| max_abs_error 最大值 | 4.800e-09 |

**这不是好消息，是同源性的必然后果。** 原因有两层：

1. B1.8 的内部累积损伤本身就是由 `mission_features` 里那四个窗统计量
   （`omega_p95`/`torque_p95`/`zero_crossing_count`/`maneuver_fraction`）
   加上遥测 `T`，经 `g_duty` × Arrhenius × `L_ref` 算出来的。
   `HI_D_obs` 用**同样的输入**跑**同样的方程**，自然复现同一条曲线。
2. 数据集里的 `T` 就是解析正弦 `T_base + T_amp·sin(2πt/5400)` 本身
   （与解析式的最大差为 0.0，**无观测噪声**）。所以"用遥测温度"这一步
   也没有引入任何测量误差。

剩余的 ~1e-9 残差只来自 `mission_features` 以 float32 存储的舍入。

### 直接后果（必须记住）

- **§8 Gate 10（`corr > 0.95`）近乎恒真。** 它只能证明"实现没写错"
  （标签固定为 `IMPLEMENTATION_AUDIT`），**不能**被引用为
  "HI 有预测能力" / "HI 能估计不可观测损伤"的证据。
- **Gate 7/8（event EOL 处 median HI ≥ 0.90、p10 ≥ 0.75）也基本由构造保证**：
  event-observed 轨迹的 EOL 定义就是"累积损伤首次达到 1"，而
  `HI = clip(D, 0, 1)`，所以在 EOL 处 HI 必然 = 1.0。实测三项统计
  （median / p10 / min）全部精确等于 1.000000，正是这一点的体现。
- 因此**真正有约束力的门是**：Gate 3（chronological-only）、
  Gate 4/5（不读隐藏真值 / 不读 `b_true`）、Gate 6（分母是常量 `L_ref`
  而非 EOL/末值）、Gate 9（删失不被强制为 1）、Gate 11（前缀不变性，
  容差 0）、Gate 13（`x_T` 无真值泄漏）。这些是"可部署且不泄漏未来"的证明，
  与同源性无关。

### 这条局限不影响 B1.9 的立项目的

B1.9 要回答的是"**能否构造一个不读隐藏损伤、只用可部署量、且与 `D>=1`
同语义的 HI**"。答案是能，而且它与失效定义同源——这恰恰是 B1.8 Gate 9
FAIL 想要的东西。但"同源"和"有预测增益"是两回事，后者要到 B2 才有资格谈。

## 2. 窗统计量的部署前提：需要星上 1 Hz 聚合

四个 `g_duty` 输入的 provenance 是 **`OBSERVABLE_DERIVED`**，不是
`OBSERVABLE_DIRECT`。原因：

- 它们是**窗内 1 Hz 序列**的聚合统计（每窗 1800 个 1 s 点）；
- 但本数据集存储的下传遥测**每窗只保留 1 个 1800 s 采样点**。

实测证据：`corr(|omega_telemetry|, omega_p95) = 0.7868`，远小于 1。
也就是说**这些统计量无法由已存储的低速遥测反推**。

**部署含义**：要在轨算 `HI_D_obs`，需要卫星**在星上按窗做 1 Hz 聚合再下传统计量**
（或直接下传 1 Hz 数据）。这是一条真实的工程约束，不能含糊成
"反正都是遥测所以可观测"。

---

## 3. 温度无观测噪声

数据集 `T` 是解析正弦本身，没有传感器噪声、没有漂移、没有量化。
真实星上热敏电阻会有这些。因此：

- `a_T(T)` 的输入在本阶段是理想的；
- 真实场景下温度噪声会通过指数放大进入 `stress`，`HI_D_obs` 的精度会下降。

本阶段**未**评估这一敏感性。若要评估，属于后续独立课题，不得在
B1.9 里追加（会改动已冻结的 protocol）。

## 4. 继承自 B1.8 的模型层局限（未改动，原样携带）

| 局限 | 说明 |
|---|---|
| Miner 线性累积 | `dD/dt = stress/L_ref` 假设损伤可线性叠加，忽略载荷顺序效应 |
| `L_ref` 是标定量 | `L_ref = 3.0 years` 是**工程标定选择**，不是实测寿命，**不是厂家规格** |
| `g_duty` 权重未重新标定 | 0.40/0.40/0.10/0.10 沿用 B1，B1.8/B1.9 都明令不得改 |
| 润滑尖峰与损伤解耦 | `lube_spike_prob = 0.01` 只作用于摩擦观测，不进入累积损伤 |
| 累积损伤不可观测 | 它是仿真内部量；B1.9 的做法是"用同源可观测量重算"，不是"从遥测反演" |

## 5. 失效定义的性质

EOL 判据 `D >= 1` 是 **`engineering_assumption_failure_definition`**。
它**不是** `manufacturer_failure_specification`，**无外部来源**，
不得在任何材料中被主张为厂家给出的失效阈值。B1.9 未改动这条定义，
只更换了健康指标的**刻度锚点**。

## 6. 本阶段未做的事

- **未训练任何 RUL 模型**：无 `target_only`、无 transfer、无基线对比、
  无任何 RUL 精度数字。`trained_any_model = false`。
- 未做 HI 候选筛选：主 HI 在 §2 protocol 里单点冻结，在任何 HI 数值被
  算出之前。协议明令不得用 RUL RMSE 选 HI，因此不存在"从若干候选中挑"的动作。
- 未改 `L_ref`、未改失效定义、未改 B1.8 正式数据、未覆盖 B1.8 feature 文件、
  未重新生成 lifetime dataset。
- 未删除旧 friction HI —— 它以 `hi_friction` 保留，供机制对比 / ablation。

## 7. 给读者的一句话提醒

> B1.9 的 14/14 PASS 说明的是"**这条 HI 可部署、不泄漏未来、且与失效定义同源**"，
> 不说明"这条 HI 能提高寿命预测精度"。后者需要 B2 的 Target-only 泛化门来回答，
> 而 B2 的结论**不得**用本阶段的 Gate 10 来预支。
